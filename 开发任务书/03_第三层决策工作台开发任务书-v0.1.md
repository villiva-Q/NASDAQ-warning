# 第三层决策工作台开发任务书

## 1. 任务目标

建立运行于Mac的第三层决策工作台。系统读取第二层冻结的研究快照，结合当前价格、组合风险和双模型研讨，形成S0—S5决策状态、价格带、预期回报区间、悲观损失、仓位上限、升级/降级/退出条件和持续监测任务。

第三层回答：

> 即使公司值得投资，当前是否值得占用资本？应以什么价格、仓位和风险预算持有？什么情况需要等待、增加、降低或退出？

第三层不得修改第二层事实、财务正常化、Q/V/R、三情景或反向DCF。发现问题时只能创建补证/重开任务，等待第二层发布新版本。

系统在H3及后续前瞻验证期间固定为paper-only，不连接券商，不生成可执行交易指令。

## 2. 启动条件

必须全部满足：

- H2已人工确认；
- `research_snapshot.schema.json` v0.1冻结；
- 5例研究快照和工时报告可用；
- 第二层正式快照具有哈希和人工审批；
- Mac上的AI Agents Co-op保持loopback，不通过未审计隧道直接公开；
- 第三层读取第二层导出目录只读；
- paper-only为Schema和后端双重硬约束。

## 3. 执行方式

- 本任务作为第三层顶层Co-op开发任务；
- 开发任务与运行期投资研讨使用不同任务模板和权限；
- Claude按L3.0—L3.8顺序管理；

- 第一阶段通过薄适配器复用现有Co-op的研讨功能；
- OpenClaw只部署NUC上的监测导入/控制API，不部署Mac本地决策界面；
- H3完成后停止，等待前瞻运行批准。

## 7. 业务规则

### 7.1 S状态

| 等级 | 状态 | 含义 |
| --- | --- | --- |
| S0 | Reject | 论点、治理、资产负债表或估值不成立 |
| S1 | Watch | 公司可研究，但价格或证据不足 |
| S2 | Verify | 关键变量等待财报、债务或行业证据 |
| S3 | Starter | 小仓纸面跟踪，允许判断继续演化 |
| S4 | Normal | 质量、估值和风险达到正常纸面持仓标准 |
| S5 | High Conviction | 多重证据一致、下行可承受且组合风险允许 |

S状态不是总分，也不表示S5企业质量必然高于S3。每次状态必须记录：

- 直接理由；
- 阻止升级的约束；
- 升级条件；
- 降级条件；
- 退出条件；
- 使用的研究快照哈希；
- 当前价格和时间；
- 复核日期；
- 人工审批。

### 7.2 价格带

系统支持：

- 观察带；
- 候选带；
- 建仓带；
- 高安全边际带。

价格带必须由冻结的价值区间、预期回报和行业下行规则计算，不能由模型自由填写。

价格下降只有在以下均成立时才能支持提高纸面仓位：

- 内在价值未同步显著下降；
- 论点和证伪条件仍成立；
- 资产负债表可承受更长逆风；
- 行业、因子和尾部风险仍在预算内；
- 相比其他候选机会成本仍有优势。

### 7.3 仓位约束

参考上限：

| 类型 | 单标的参考权重 |
| --- | ---: |
| 跟踪型Starter | 0.5%—1.0% |
| R0普通高质量 | 2%—3%；高确信且组合允许时4%—5% |
| R1 | 通常不超过3% |
| R2特殊情形 | 通常不超过1%—2% |
| 单标的绝对上限 | 5%—7%，需额外审批 |

```text
仓位上限
  = min(
      风险等级上限,
      单标的可接受损失预算 / 悲观情景损失率,
      流动性上限,
      行业与相关性剩余额度,
      人工审批上限
    )
```

组合约束初始值：

- 单一行业20%—25%；
- 相同风险因子/宏观传导链25%—30%；
- R2权重合计暂不超过10%；
- R2另满足 `Σ(权重×悲观损失率) ≤ 预登记压力损失上限`；
- R3仓位恒为0；
- Q/V分数不能线性映射仓位。

所有比例均为paper portfolio治理参数，必须版本化并注明待前瞻验证。

### 7.4 退出优先级

1. 论点或证伪条件失效；
2. 价格进入乐观价值区且未来回报不足；
3. 更优机会替代；
4. 行业、因子、流动性或尾部风险超限；
5. 关键数据无法继续核验。

短期价格波动本身不是退出或加仓条件。

### 7.5 监测触发

| 触发 | 动作 |
| --- | --- |
| 股价相对上次估值变化超过15% | 更新安全边际和反向DCF显示；必要时创建第二层重开任务 |
| 新10-Q/6-K | 重开第二层季度、TTM、证伪和资产负债表流程 |
| 新10-K/20-F | 重开第二层完整研究 |
| 重大8-K、融资、并购、诉讼或管理层变化 | 即时创建事件复核 |
| 每半年 | 比较候选机会成本和组合相关性 |
| 每年 | 第一层因子和行业偏差复核任务 |

第三层不得在第二层重开完成前自行更新内在价值。

## 9. AI Agents Co-op 运行期适配

### 9.1 适配原则

- 第三层不复制完整Co-op代码；
- `decision_adapter`通过本地API或受控任务文件创建研讨；
- 每个研讨固定引用一个 `research_snapshot_hash`；
- 研讨双方只读研究快照和允许的组合摘要；
- 模型不能读取其他case、代码仓库或生产密钥；
- 研讨输出先形成 `decision_draft`，人工批准后才生成正式记录；
- 主持人插话、追加轮次和总结全部进入审计链；
- 模型切换记录模型版本和提示词版本。

### 9.2 研讨模板

至少包含：

1. 正方：为什么当前价格可能提供足够回报；
2. 反方：市场可能正确、永久损失如何发生；
3. 数字核验：哪些结论依赖脆弱假设；
4. 组合视角：机会成本、相关性和压力贡献；
5. 状态建议：S0—S5及阻止升级的变量；
6. 证伪与监测：下一次改变结论的证据；
7. 分歧摘要：不强行求共识。

模型可以建议S状态和纸面仓位区间，但确定性约束引擎负责校验；超限建议必须被拒绝并显示约束来源。
