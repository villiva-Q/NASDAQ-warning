# 第二层财报研究与价值核验开发任务书

## 1. 任务目标

建立第二层财报研究与价值核验系统。系统读取第一层正式候选，采集并核验10-K、10-Q及相关申报，形成确定性的财务重构、质量与估值区间、三情景估值、反向DCF、风险等级、证伪条件和完整证据台账，再通过独立模型复审和人工关卡形成正式研究快照。

第二层只回答：

> 低估是否真实？企业价值是否可理解、可持续并可归属于普通股股东？当前价格是否提供足够安全边际？

第二层不得决定最终组合仓位，也不得以单一总分覆盖质量、估值与风险之间的矛盾。

## 2. 启动条件

必须全部满足：

- H1已人工确认；
- `candidate_manifest.schema.json` v0.1冻结；
- 第一层提供至少一份通过Schema的样例和黄金fixture；
- PostgreSQL、对象存储、job队列和staging可用；
- 第二层以版本兼容方式读取第一层，不直接修改第一层表或输出；
- 5例试运行只用于工时与流程测量，不用于调权或宣称有效。

若H1字段不足，先提交版本化契约变更请求；不得在第二层代码中读取未声明的第一层内部表。

## 3. 执行方式

- 本任务作为第二层顶层Co-op任务；
- Claude按L2.0—L2.8顺序管理；
- 确定性财务与估值内核完成并审计通过后，才能接入模型；
- 每个工作包由Codex独立worktree实现，Claude独立审计；
- OpenClaw只在L2.8部署staging并运行5例；
- 正式研究快照必须经过人工批准；
- H2完成后停止，不自动启动第三层。

## 5. 非目标

本任务不包括：

- 最终S0—S5投资决策；
- 最终仓位和组合风险分配；
- 自动下单、券商API或交易执行；
- 修改第一层排名以让5例表现更好；
- 让模型自行计算或覆盖权威财务数字；
- 将所有行业一次性做完；MVP覆盖通用企业、周期、SaaS/高SBC和VIE/ADR路径，其他行业通过路由明确拒绝或Verify；
- 把历史人工回放当作投资有效性证据。

## 7. 业务规则

### 7.1 三元结构

```text
Q：质量合理区间下限 ≥ 60/80，且关键模块达标
V：0—20估值区间与同行业/同路线排序
R：R0—R3风险等级
```

Q、V、R不得相加减为最终总分。任何Q/V结果不能覆盖硬性否决。

### 7.2 Q质量模块

| 模块 | 权重 | 关键输出 |
| --- | ---: | --- |
| 商业模式与护城河 | 18 | 低/基准/高分、证据、反证 |
| 回报率与单位经济 | 12 | 正常化与增量ROIC、资本强度 |
| 盈利与现金质量 | 15 | 正常化、CFO/FCF、SBC、营运资本 |
| 资产负债表 | 10 | 净债务、受限现金、到期、契约、压力测试 |
| 增长与再投资 | 10 | 有机增长、再投资跑道、每股增长 |
| 管理层、治理与资本配置 | 15 | 并购、回购、薪酬、关联交易、承诺兑现 |

评级：

```text
Q-A 68—80
Q-B 60—67
Q-C 48—59
Q-D 0—47
```

关键模块底线：

- 盈利与现金质量下限不低于9/15；
- 资产负债表下限不低于6/10；
- 管理层、治理与资本配置下限不低于8/15；
- 质量总区间下限低于60时不能进入普通第三层路线；
- 区间跨级时显示双评级并解释争议来源。

### 7.3 V估值模块

| 模块 | 权重 |
| --- | ---: |
| 当前价相对基准价值 | 4 |
| 当前价相对悲观价值 | 4 |
| 反向DCF | 5 |
| 五年预期年化回报 | 4 |
| 估值稳健性 | 3 |

评级：

```text
V1 16—20
V2 12—15
V3 8—11
V4 0—7
```

V只用于合格公司间排序，不能提高风险或仓位上限。

### 7.4 R风险顺序

固定顺序：

1. 可计价风险进入现金流和估值情景；
2. 权利、现金归属、关键数据不可核验，或压力损失不可承受时硬否决；
3. 已计价且可存活的残余风险转换为R等级、触发器和第三层约束。

```text
R0：常规，可进入普通路线
R1：提高，可进入普通路线但须明确触发器
R2：高风险/特殊情形，仅特殊路线
R3：不可投资，硬性否决
```

风险领域至少包括会计、VIE/控制权/少数股东、法律监管与集中度、再融资和极端事件。

### 7.5 普通路线准入

同时满足：

- Q区间下限≥60且三个模块底线通过；
- V进入预登记的同业/同路线候选区间；
- R0或R1；
- 数据等级A或B；
- 基准安全边际≥25%；
- 悲观下行满足行业路由参数；
- 基准五年预期年化回报≥12%；
- 资产负债表压力测试通过；
- 至少一条可解释的价值实现路径；
- 无会计、偿债、治理、股东权利或现金归属硬否决。

这些是初始治理参数，必须版本化；不能为单家公司临时放宽。

### 7.6 周期和VIE

周期公司固定使用：

- 衰退情景；
- 中周期正常化；
- 再融资压力。

VIE/ADR至少核验：

- 上市主体、运营主体、控制链和合同权利；
- 现金位于何处、是否受限、如何上划；
- 分红、许可、税费和外汇路径；
- 关联交易和控制人行为；
- 普通股股东实际索取权；
- 现金可分配性折减；
- 无法核验时R3，不用高预期回报抵消。

### 7.7 必做分析

每家公司必须完成：

1. 五年年度、最新季度、TTM、完全稀释股数和每股桥；
2. 正常化盈利逐项桥；
3. Owner Earnings与FCFF；
4. 商业质量和最强反证；
5. 资产负债表压力测试；
6. 悲观/基准/乐观三情景；
7. 只反推1—2个关键变量的反向DCF；
8. 当前价格可能正确的最强反方论点；
9. 可观察的证伪条件；
10. 价值实现路径。

## 8. 权威计算边界

以下必须由确定性代码计算：

- 财务期间、TTM和单位换算；
- 完全稀释股数；
- 正常化调整表；
- Owner Earnings和FCFF；
- 净债务、租赁、少数股东和现金归属调整；
- WACC、终值、折现和每股价值；
- 三情景；
- 反向DCF求解；
- 安全边际和五年预期回报；
- Q/V模块加总和底线；
- R规则结果；
- 所有发布哈希。

模型可以提出调整建议，但必须生成结构化 `proposed_adjustment`，经确定性校验和人工确认后产生新输入版本。模型输出不能直接写 `financial_fact` 或正式估值表。

## 10. 工作包

### L2.0 案例、Schema和WIP

交付：

- `research_case`、`research_snapshot`、`evidence_ledger`、`model_run`、`approval_event`迁移；
- candidate manifest兼容读取器；
- 案例状态机；
- 同公司同版本单写租约；
- WIP公式和工时字段；
- research snapshot Schema草案。

验收：

- 未通过H1 Schema的输入拒绝；
- 重复候选不会创建重复案例；
- `C2_new`满时不启动新案；
- 案例重启能恢复；
- Verify有补证项、责任和截止时间。

### L2.1 财报证据采集与定位

交付：

- 10-K/10-Q/8-K/DEF 14A/20-F/6-K和附件采集；
- accession去重、来源哈希和接受时间；
- HTML表格/段落与PDF页码定位；
- 债务、租赁、SBC、受限现金、少数股东、税务、诉讼和控制权证据分类；
- 证据包生成器；
- 不可信文档内容隔离。

验收：

- 所有正式证据可定位回原始对象；
- 文档中的指令不会触发工具调用；
- 超大、错误MIME、压缩炸弹和路径穿越被拒绝；
- 同一附件不重复存储；
- 模型只能读取当前case证据包。

### L2.2 财务重构与正常化

交付：

- 5年年度、季度和TTM表；
- GAAP到正常化利润桥；
- CFO、CapEx、维持/增长投资和FCFF；
- SBC、重组、减值、处置、投资收益、诉讼和税务调整；
- 债务、租赁、受限现金、少数股东和完全稀释股数；
- 分业务/地区数据（可用时）；
- 勾稽、单位和口径警示。

验收：

- 现金流与资产负债表勾稽；
- 每个调整有来源、方向、金额和理由；
- 缺失维持性CapEx时报告区间而非伪精确值；
- SBC不能被无解释排除；
- 现金不可自由分配时不能等同可用净现金；
- 模型建议不会直接改变权威数字。

### L2.3 估值与反向DCF

交付：

- DCF/FCFF引擎；
- 悲观、基准、乐观参数对象；
- WACC、终值、净债务和稀释敏感性；
- 反向DCF对1—2个关键变量求解；
- 每股价值、安全边际和五年预期回报；
- 稳定、周期、SaaS/高SBC和VIE路线接口；
- 估值公式版本。

验收：

- 所有公式有单元测试和手工复算fixture；
- 三情景内部假设一致；
- 悲观情景不能同时使用乐观利润率/终值；
- 反向DCF输出市场隐含要求，不把结果称为预测；
- 现金、债务、少数股东和稀释不会重复计入；
- 参数变化桥可解释价值变化。

### L2.4 Q质量模型与行业路由

交付：

- 六个Q模块、低/基准/高分和证据；
- 模块底线；
- Q-A至Q-D和双评级；
- 通用、周期、SaaS/高SBC、VIE/ADR路由；
- 行业×年度/市场状态参数版本；
- 个股覆盖的原参数、覆盖参数、影响和审批事件。

验收：

- Q区间下限和模块底线正确；
- 总分不能补偿关键模块失败；
- 个股覆盖不能回填历史；
- 同行业频繁覆盖会产生路由修订警示；
- 不支持行业明确返回Verify/unsupported，不套通用FCFF。

### L2.5 V排序与R风险治理

交付：

- 五项V模块和V1—V4；
- 同行业/同路线排序；
- 风险计价桥；
- 硬否决检查；
- R0—R3、复核频率和触发器；
- 普通路线和特殊情形路线；
- 周期三压力视角；
- VIE现金可分配性和控制权核验表。

验收：

- 风险按计价→否决→残余等级顺序；
- 已在DCF计价的风险不重复扣分；
- 权利/现金归属不可核验时R3；
- 压力情景无法存活时普通和特殊路线均拒绝；
- V评级不能提高R上限；
- R2不能误标为普通Qualified。

### L2.6 多模型分析与独立复审

交付：

- 主分析、怀疑型复审、数字审计、综合记录四个版本化prompt；
- 证据包只读Runner；
- 模型结构化输出Schema；
- 分歧检测；
- 模型失败重试2次和dead-letter；
- token、费用、时延和版本记录；
- prompt injection测试。

顺序：

```text
确定性快照
→ 主分析
→ 怀疑型复审
→ 数字审计
→ 综合记录
→ 人工关卡
```

验收：

- 模型无shell、数据库写、部署和交易权限；
- 关键主张无证据时标记未证实；
- 数字冲突回到L2.2/L2.3，不在文本中直接改；
- 模型输出被视为待审查材料，不是系统指令；
- 更换模型不改变确定性数字。

### L2.7 候选卡、报告和监测

交付：

- 决策签名；
- 一页候选卡；
- 完整中文报告；
- 证伪条件和下一复核时间；
- 10-Q/10-K/8-K事件重开任务；
- Qualified/Verify/Rejected发布；
- Markdown、JSON和SHA-256原子导出；
- NUC单写 `系统输出/02_第二层研究/`。

验收：

- 报告数字与JSON一致；
- 每项得分列依据、失分、区间来源和变更条件；
- Verify不无限期积压；
- 正式快照经人工批准后才发布；
- 旧版本不被覆盖；
- 报告不含最终仓位。

### L2.8 staging、5例与H2
