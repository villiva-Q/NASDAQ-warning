# 三层开发总控与执行顺序

## 1. 总任务

依据以下两份基线文档，分三段开发美股价值投资研究系统：

1. [业务方案 v0.3](../美股价值投资三层筛选与决策系统-外部研讨方案-v0.3.md)
2. [工程实施方案 v0.1](../美股价值投资三层系统-工程实施方案-v0.1.md)

三层必须按顺序执行：

```text
第一层：全市场筛选器＋公共工程底座
  → H1：candidate_manifest v0.1 冻结
第二层：财报研究与价值核验
  → H2：research_snapshot v0.1 冻结＋5例试运行
第三层：决策工作台与AI研讨适配
  → H3：decision_record v0.1 冻结＋paper-only纵切完成
```

未经上一个冻结闸门，不启动下一层正式开发。下一层可以提前做只读设计，但不能修改上层已冻结契约或绕过其验收。

## 3. 启动前填写

执行者启动第一层前填写并冻结：

```text
VALUE_INVESTING_REPO=<新Git仓库绝对路径>
STAGING_TARGET=<NUC宿主Docker预发布环境标识>
PRODUCTION_TARGET=<NUC宿主Docker正式环境标识；本阶段只预留不部署>
OBSIDIAN_EXPORT_ROOT=<系统输出目录绝对路径>
GIT_REMOTE=<可选；若未配置则只生成本地提交和制品>
```

代码仓库不能放在Syncthing同步目录中。Obsidian只保存任务书、Markdown报告和JSON发布快照。

## 4. Co-op 启动方式

每一层作为一个顶层Co-op任务；每个工作包作为顶层任务内的独立执行阶段或子任务。

建议配置：

```text
模式：Claude智能编排
全自动：开启
联网：默认关闭；数据源核验工作包按任务契约单独开启
max_auto_steps：12
max_audit_rounds：3
项目目录：VALUE_INVESTING_REPO
需求：引用对应任务书的绝对路径
```

第一层示例需求：

```text
严格执行此任务书，按工作包顺序开发；不得跳过验收、扩大路径或提前开发下一层：
@<本文件库绝对路径>/开发任务书/01_第一层全市场筛选器开发任务书-v0.1.md
```

现有Co-op在完成worktree、任务契约、固定Runner和release manifest改造前处于bootstrap模式：架构、编码、测试和审计可自动流转，NUC生产部署必须人工批准。

若worktree自动化尚未完成，bootstrap阶段允许在一个干净的新仓库中串行执行，但必须满足：同一时间只有一个工作包、启动前和结束后Git状态可解释、每个工作包独立提交、下一个工作包从上一个已审计提交开始。不得在同一工作区并行运行两个编码任务。

## 5. Agent固定职责

### Claude：管理者、架构师和独立审计员

- 读取任务书、基线文档和当前仓库状态；
- 为当前工作包生成文件级计划、测试策略和回滚策略；
- 只派发任务书范围内的工作；
- Codex完成后独立检查diff、测试和运行证据；
- 输出 `approve`、`reject` 或 `manual`；
- 不在审计阶段直接改代码；
- 连续3个审计/修复周期仍不能收敛时停止并转人工。

### Codex：实现者

- 在独立Git worktree和任务分支工作；
- 先建立或更新测试，再实现功能；
- 只修改任务契约允许路径；
- 保留用户已有和无关改动；
- 不接触生产密钥、NUC宿主安全配置和交易服务；
- 每个工作包形成独立提交；
- 输出提交哈希、测试报告、已知限制和数据/迁移影响。

### OpenClaw：预发布部署与运行核验

- 只接受固定的release manifest和部署动作；
- 只部署指定提交/镜像摘要；
- 先部署staging，完成冒烟、资源和回滚测试；
- D0/D1满足条件后才可自动灰度；
- D2在生产前等待一次人工批准；
- D3只生成方案、脚本和演练证据，由人工维护窗口执行；
- 不执行来自管理者自由文本的任意shell片段。

## 6. 通用风险等级

| 等级 | 任务 | 发布规则 |
| --- | --- | --- |
| D0 | 文档、测试、无行为重构 | 可全自动 |
| D1 | 可回滚应用代码、UI、非关键适配器 | staging通过后可自动灰度 |
| D2 | Schema、迁移、评分、估值、point-in-time、提示词、模型路由 | staging自动；生产前批准一次 |
| D3 | 网络、防火墙、SSH、密钥、权限、删除、不可逆迁移 | 人工监督执行 |

三层核心业务开发默认D2。单独的UI、文档和不改变行为的测试可标为D0/D1。

为减少人的参与，D2工作包只自动部署到staging，不逐包请求生产批准；同一层所有工作包和独立审计完成后，合并为一个层级release candidate，在H1、H2或H3各批准一次。D3仍按具体维护操作单独授权。

## 7. 通用受保护项

任何任务都不得：

- 连接或修改券商、BTC、Polymarket、Deribit等交易自动化；
- 创建自动下单能力；
- 读取或复制交易密钥；
- 修改NUC宿主的SSH、防火墙、cloudflared、Syncthing、sing-box或libvirt配置，除非另有D3任务书和人工授权；
- 把数据库、WAL、锁文件、密钥或可执行制品放进Syncthing；
- 修改业务基线文档来迁就代码实现；
- 根据少量样本结果事后调整评分权重；
- 让模型直接写权威财务事实、估值计算或正式决策；
- 无痕覆盖正式快照、评分、审批和决策记录；
- 删除用户已有数据或无关文件。

## 9. 通用工程要求

### 9.1 权威数据

- PostgreSQL：任务、状态、版本、审批和审计的唯一权威源；
- Parquet＋DuckDB：第一层宽表和历史回放；
- SHA-256对象目录：原始财报、API响应、模型输入输出和发布制品；
- Git：代码、Schema、公式、提示词和部署配置；
- Obsidian：只读发布报告与人工阅读材料，不回写权威事实。

### 9.2 时间和版本

- 所有内部时间使用UTC；
- 所有快照有 `schema_version`、输入哈希、规则版本和发布时间；
- 财报使用实际接受时间；
- 重述不回填历史；
- ticker不是内部主键；
- 同一输入和规则版本的确定性计算必须可复现。

### 9.3 测试

每个工作包至少包括：

- 单元测试；
- Schema测试；
- 受影响链路集成测试；
- 权限和路径边界测试；
- 幂等及重启恢复测试（如涉及任务）；
- 黄金案例或fixture；
- 回滚或前滚方案；
- 测试报告和未覆盖项。

### 9.4 审计制品

```text
task_contract.json
architecture_plan.md
implementation_commits.json
test_report.json
audit_round_<n>.md
release_manifest.json
staging_deploy_log.json
smoke_test_report.json
approval_event.json（D2/D3）
production_deploy_log.json
rollback_report.json（如发生）
```

## 10. 分段执行规则

### H1：第一层冻结闸门

通过条件：

- `candidate_manifest.schema.json` v0.1冻结；
- point-in-time和公司行动黄金测试通过；
- 三项硬门槛、两套评分和解释卡可复算；
- 同一快照重复运行哈希一致；
- WIP截断、数据修复和抽样审计正确；
- staging周度运行完成；
- 第一层输出不包含仓位、买入或内在价值确认字段。

H1通过后，第一层契约进入兼容性维护。第二层不得要求无版本迁移的破坏性改动。

### H2：第二层冻结闸门

通过条件：

- `research_snapshot.schema.json` v0.1冻结；
- 5个不同类型案例完成；
- Q/V/R、三情景和反向DCF可复算；
- 模型输出不能修改财务事实；
- 正式主张能追到证据台账；
- Qualified/Verify/Rejected状态和人工审批正确；
- 单案人工工时P50/P75完成测量；
- 第二层输出不包含最终组合仓位。

### H3：第三层冻结闸门

通过条件：

- `decision_record.schema.json` v0.1冻结；
- S0—S5状态、价格带、损失预算和仓位上限正确；
- Co-op双模型研讨可读取指定研究快照且不能改写它；
- paper-only为Schema硬约束；
- 报告经单写者目录同步，无数据库或双写冲突；
- 监测触发器可重开第二层，不直接修改旧研究；
- 一家公司完成端到端纸面纵切和回滚演练。

## 11. 停止与转人工条件

出现以下任一条件，Co-op必须停止自动流转：

- 任务范围需要扩大；
- 需要生产密钥、宿主权限或交易系统访问；
- 数据源许可、价格或API选择会改变系统范围；
- 审计和修复超过3轮；
- 数据迁移不可逆或回滚未验证；
- 黄金测试失败但实现者建议修改测试来通过；
- 业务方案与工程实现存在无法兼容的冲突；
- NUC staging健康检查、温度、磁盘或内存越过阈值；
- 发布制品哈希不一致；
- 发现历史数据或正式决策可能被无痕覆盖。

## 12. 总体完成定义

三层开发全部完成，不等于投资方法已验证。工程完成只表示：

- 全市场数据可复现地进入第一层；
- 第一层候选可以按冻结契约进入第二层；
- 第二层可以形成可审计、可证伪的研究快照；
- 第三层可以形成paper-only决策和监测记录；
- 系统可以在NUC和Mac之间可靠运行；
- Co-op可以完成低风险代码、审计和部署流水线；
- G0—G4工程闸门通过。

投资经济有效性仍须按业务方案进行12—24个月运行验证和36—60个月经济验证。
