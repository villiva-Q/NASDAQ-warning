用户确认询问用途/保存限制/最低费用的邮件已发送，并批准真实落盘与研究可用性测试。下列结果来自 NUC 实际执行，不是文档预测。账户方案按用户提供的 Basic 说明记录。

本轮合计 20 次请求：19 次 HTTP 200，1 次预期的历史范围 HTTP 403。采集和两个独立离线验证进程均退出 0。

## 时间戳差异

同一个 2024-11-01 交易日，AAPL 单股 Custom Bars 的 t 为 `2024-11-01T04:00:00Z`；Grouped Daily 的 t 为 `2024-11-01T20:00:00Z`。

[Custom Bars 文档](https://massive.com/docs/rest/stocks/aggregates/custom-bars)将 t 定义为聚合窗口起点；[Daily Market Summary 文档](https://massive.com/docs/rest/stocks/aggregates/daily-market-summary)将 t 定义为终点。接入时需保留来源语义并按明确交易日/时区比较，不能将任一 t 充当数据公开时间。公司身份的 SEC 派生字段仍需单独执行提交/公开时间校验。

## 本地保存、恢复和离线重算

两批原始响应合计 1,193,695 字节，保存在仓库外：

- `/srv/cargoq/data/massive-basic-evaluation/20260908-owner-storage-test`

每批包含真实 raw JSON、manifest.json、derived_report.json、backup.zip、collection_summary.json、offline_verification.json。后者真实确认：

- 采集进程退出后，新 Python 进程重算结果一致。
- `unshare --net` 仅隔离测试进程网络，网络连接不可用；验证路径不读取 API key。
- 从 ZIP 恢复的独立副本得到相同结果。
- 故意修改恢复副本后，快照完整性检查识别出损坏；原始文件及备份保留。

两次离线检查分别在 11:45:24 UTC、11:46:57 UTC 完成。本次验证了持久存储和恢复机制，没有重启 NUC，没有实际等待数月，也没有实施自动删除/轮转计划。故不能将这些结果写成长期自然时间耐久性或无限期保存许可已证实。

代表样本的 19 次请求耗时 234.88 秒，串行请求启动间隔 13 秒。全市场日终接口通过后，批量日更新不必按 300 只股票逐只发 300 个价格请求；一日价格可由一次汇总请求本地筛选。但身份与公司行动仍需各自处理，这不是完整 300 股研究链路已通过。[官方方案说明](https://massive.com/pricing?product=stocks)
