## 当前组织方式

|---|---|---|
| 管理者 | GPT-6 Astra | 规划、拆分、顺序派发、检查产出、决定修复或完成；只读，不直接修改代码 |
| codex | GPT-5.6 Terra | 编码与缺陷修复 |
| tester | GPT-5.6 Terra，独立会话 | 编写/执行适用测试、复现问题、返回证据 |

| claude（界面仍称 Claude Code） | 当前实际 GPT-5.6 Sol | 通用分析、架构和旧流水线审计 |
| openclaw | 主模型 GPT-5.6 Sol | NUC 部署、服务检查、运行维护；内部子代理为 GPT-5.3 Codex Spark |

“子代理”主要是独立执行会话，通过任务指令、阶段输出和项目文件交接，不应假设持续在线或会自行互通上下文。

智能管理模式在单任务内顺序调用角色，不支持一次派发多个角色再并行汇总。不同任务虽可同时运行，但尚无统一并发调度或自动工作区隔离；管理者必须避免多个写者修改同一目录，按需使用独立 checkout/worktree。

典型次序可为编码 → 测试 → 一次独立审查 → 必要修复与复测 → 已获授权的部署 → 运行验证。简单任务不机械调用全部角色，不因新增角色重复已完成验收。旧固定流水线仍为架构 → 编码 → 审计 → 部署；新增角色主要由智能管理模式按需选择。
