## 2. 已确认的问题与修复边界

### A. 把 frame 当成原始财务记录的必填条件

`packages/connectors/sec_edgar.py` 的 `SecSampleScreenParser._fact` 要求每条 observation 包含 `frame`，再用 frame 正则过滤。

原归档中的 KO 2024-09-27 现金 13,938,000,000 USD、2024 年至该日 CFO 2,854,000,000 USD 和 CapEx 1,261,000,000 USD 均属于选定 accession，但没有 frame；它们被丢弃。CAT 的季度稀释股数 486,700,000 与 YTD 股数 491,700,000 同样已在源中但没有 frame。

SEC 官方将 frames 描述为按日历期间匹配、选取最近申报事实的聚合形式，并提示公司财年不一定与日历期间一致。这不支持把 frame 用作每条原申报事实的必需身份。[SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

**修复要求**：按 accession、接受时间、concept、unit、start/end 和明确期间类型识别事实；frame 只保留为来源元数据。不能简单删一条检查，然后继续用字符串排序挑唯一值。保持未来申报不可见、冲突不静默取大值。

### B. 10-Q 的 YTD 与单季度需要分开保存

同一个 10-Q 同时含季度和累计观察。例如 KO 净利润存在：

- 2024-01-01—2024-09-27：8,436,000,000 USD；
- 2024-06-29—2024-09-27：2,848,000,000 USD。

baseline `parse` 对 10-Q 统一设置 `reporting_period=quarterly`。当前 frame 拒绝掩盖了不少 YTD 记录；只放宽 frame 会把 6/9 个月累计数据误标成季度。

**修复要求**：从原始期间构建 quarter/YTD/annual，不以 form 直接推导金额期间；保留同一 metric 的多个期间。TTM 继续使用四个可比季度或 FY+当期YTD−去年同期YTD，不能乘四年化；53 周或非日历财年需明确支持情况。

### C. 股数原始名称正确，但下游用途越过了语义边界

L1.8 `_reported_diluted_share_observation` 确实标注了 period-weighted-average；但 `ScreeningInputAdapter._fully_diluted_shares` 在 `require_reported_diluted_shares=True` 时直接返回这个数，`_market_cap` 再将其乘以 price 和 FX。

PARA 的 670M 是该季 EPS 加权平均稀释股数。10-Q 的 EPS 注释列示 basic weighted average 667M，加 SBC 稀释影响 3M，得到 670M；它不是该报价日时点普通股本的证明。[PARA 2024Q3 10-Q，EPS 注释](https://www.sec.gov/Archives/edgar/data/813828/000081382824000079/para-20240930.htm)

既有 `670,000,000 × 10.84 = 7,262,800,000` 算术可复算，但不能只凭这一算式确认已核验的时点市值或 fully-diluted valuation equity。原结果保留为历史 pilot 输出，本包不发布替代市值。

**建议的具体口径**：把时点普通股本、EPS 加权平均基本/稀释股数、估值时点潜在稀释桥分别表达；保留现有投资规则要求的完全稀释估值分母，但不能拿期间 EPS 分母直接代替。若 `market_capitalization` 继续表达完全稀释估值权益，应明确命名/文档及单独的普通股时点市值，不让同一字段同时表示两者。多股类、ADR 还须闭合证券类别和单位。

这是下一包需要明确的字段语义决定；不要求重新审查所有历史工程，也不把 basic shares 当作 diluted shares 的自动回退。

### D. 财务标准化并未给 L1.8 的 TTM 消费者送入历史原始观察

`apps/screener/l18_limited_sample.py::_stage_company` 调用 `ScreeningSourceInputs` 时仅传 `observations`，没有传 `raw_facts` 或 `historical_raw`，这两个字段默认空元组。

`ScreeningInputAdapter._ttm_amount` 读取的是 `source.raw_facts`，不是写入数据库的单份 snapshot。因此，即使放宽 frame 并将最新财报的 CFO 落表，现有 L1.8 调用仍不能给 TTM 评分分子提供数据。完整接线需要多申报、可比期间及各自 known-at。

L1.9 runner 则更早结束：没有上述财务流程，在普通对象上直接写 `required_fundamentals_unknown`。L1.10C 应复用既有适配/评分接口补齐新批量路径，而非复制一套公式。

### E. 映射与归档范围不足，应分别处理

- 当前 parser 只映射 8 个 metric，没有 debt、revenue、restricted cash、租赁等完整 EV/门槛输入生产者。不能将公司归档中有相关 concept 等同于“已核验总债务”；债务不同组成不能重复相加。
- TSM 原归档存在 IFRS 2023 年现金 1,465,427,800,000 TWD、CFO 1,241,967,300,000 TWD、利润 851,027,700,000 TWD；同时存在 USD 版本。当前 US-GAAP/USD tag 为空不等于财报为空。换算依据、主报告币种与 ADR ratio 未闭合前，不选择便利的 USD 数值强行评分。
- KO 封面普通股数为 2024-10-22 的 4,307,797,138；SNOW 为 2024-08-20 的 335,200,000。它们在 cutoff 前披露，但与财报期末不同，需独立 observation date 及股本桥，不能修改 observation date 伪装期末值。
- JPM 的 submissions 顶层 recent 没有 cutoff 可见目标，但 `filings.files` 中有覆盖 2024-10-23—11-24 的 `CIK0000019617-submissions-009.json`。本包记录分页缺口，不再抓取，因为 JPM 本次仍属于 unsupported 负例。后续历史财报消费者应按公开索引补齐分页。
