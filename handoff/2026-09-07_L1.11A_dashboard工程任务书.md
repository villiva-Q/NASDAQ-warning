## 目标和默认技术方向

将草图变成仓库内可运行、可重复更新的只读 dashboard，第一层来自现有真实运行结果。优先以现有 Python 报告导出能力生成稳定 JSON 视图模型和静态页面，复用已有依赖；若现有服务更适合承载则采用最小只读路由。无需另建前端平台、数据库表、实时推送、账户或审批框架。

对本包使用者提供固定 CLI/启动步骤：给定本地运行报告或运行目录，生成/刷新页面；默认 loopback 预览。发布产物应能离线查看，或明确给出本地服务方式；禁止只交付写死样例的 HTML。普通刷新只读取已有输出，不触发 SEC 抓取、重新评分、数据库写入或正式候选发布。

## 功能范围

1. 三层分别呈现。L1 为已实现数据视图；L2 为财报研究、财务重构、估值和证据的信息架构；L3 为决策状态、价格带、风险预算和持续监测的信息架构。L2/L3 明确未启动、无业务输出，不实现估值计算/决策引擎/交易功能。
2. L1 结果集与公司选择，展示五项已支持财务指标 CFO、CapEx、净利润、EBIT、SBC。金额有单位；展示可用、缺失、不支持、失败等原始语义，0 不变成缺失，负值不取绝对值，缺失不补零。可用指标计数由结果计算，不把可用等同候选通过。
3. 展示本次 cutoff、SEC acceptance/申报、期间、选中 TTM 组成及来源引用。可对照同一公司两个运行时点，保持 run/input/config/rule 身份独立。优先读取现有 v3_metric_report、输入快照及运行输出，不在 JavaScript 内重新实现财务选择/TTM规则。不存在的字段显示未知/未提供，不从文件名猜来源。
4. 数据缺口视图从实际结果显示原因；可保留标为项目待办的汇总。C-2 KO 有财务值、C-3 主配置 KO SIC2080 不支持属于不同结果，不互相覆盖。当前 ticker/metadata 不得当历史身份；market fixture 必须明确标识，不能显示真实市场覆盖已闭合。
5. 运行与工程视图分开显示运行结果和项目里程碑。C-3 财务样本与 L1.9 的 300 家工程试跑分开计数。没有正式候选 manifest 就显示未发布，不伪造排名。main/分支/验收状态若没有可读机器来源，可使用有日期和来源的项目状态清单，不能伪称实时 Git 或数据库状态。
6. 缺文件、尚无结果、未知报告版本和部分损坏输入有明确可理解状态，不显示成功的旧样例。传入的公司名、原因和来源按文本呈现；路径只用于预定报告读取，不将其作为可执行命令或任意文件下载端点。沿用现有来源 hash，不增加逐事件证明链。
7. 支持桌面和约360px窄屏，键盘可用；数据密集表格可以局部横向滚动。首次打开能看到真实输入概要、公司矩阵与来源明细。页面默认不联网加载第三方库。
