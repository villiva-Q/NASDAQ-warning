## 实现与边界

`LimitedSamplePreparer` 复用既有 SEC connector、response cache、原始归档、限流和重试。它以 cutoff-visible companyfacts duration 候选和 submissions `filings.files` 目录范围保守选择所需历史页，而非把固定天数当充分性证明。gzip body 按原始 bytes 归档，来源 URL、真实 `fetched_at` 和 SHA-256 保留；parser 以 `submissions_history:<SEC filename>` 消费历史页，并最终按 `acceptanceDateTime` 判 PIT，`filingDate` 不替代 acceptance。

显式 opt-in 入口 `scripts/run_l110c2_sec_history_v3.py` 只支持冻结的 KO/CAT/SNOW/PARA/TSM/JPM 与 cutoff `2024-11-18T00:00:00Z`。`prepare` 写独立 `limited_sample_financial_period_v3.json`，`run` 实际经过 repositories、C-1 `stage_company_financial_period_v3`、v3 raw-facts snapshot 和既有 adapter，并返回不可变 summary/manifest/逐指标报告引用。默认旧 `run()` 仍走 v2；旧输入、旧报告和失败 run 不被覆盖。

完整归档可用 `--replay-input` 隔网重放。部分失败用 `--recover-input` 在新的 workdir 继续：成功来源按原始 identity 重登记，只请求失败公司/缺页；每一跳输入与目标路径不可变。相同失败事实允许相同 bytes/hash，契约是独立引用及下一跳可继续，成功输入则产生独立 hash/run。来源登记和 repository run 均保持幂等单写者语义。
