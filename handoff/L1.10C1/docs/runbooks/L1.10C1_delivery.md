# L1.10C-1 NUC 交付记录

本工单受《内部项目最小防护与工程纪律 v1.0》约束。未新增第4节所列防护；本记录只整理已验证事实，不改变业务规则，不部署、不合入 main，也不自行宣布整个工作包完成。

## 交付入口与兼容边界

- 显式新入口为 `LimitedSampleRunner.stage_company_financial_period_v3(...)`；parser 调用使用 `output_version="l1.10.financial-periods.v3"`。默认 `_stage_company` 仍走 `l1.7.raw-interchange.v2`，不会让新输入静默改写旧 L1.8/L1.9 运行。
- v3 将实际消费的期间事实写为 `l1.10.financial-period-input.v3` 内容寻址对象，并在 `source_summary.financial_period_input_snapshot_reference` 返回引用。调用者用同一 `FileObjectStore.get(reference)` 回读 JSON；其中保留 parser version、cutoff、关联标识及每条事实的 accession、接受时间、concept、unit、start/end、period kind 和来源。
- parser 能消费主 submissions 以及调用者显式提供的 `submissions_history:<SEC filename>` 顶层列数组。识别 `filings.files` 是已有能力；自动下载这些公开历史页仍是后续批量采集调用者的责任，当前实现不会自行联网补页。
- 现有 adapter 直接消费 `ScreeningSourceInputs.raw_facts`，沿用四个可比季度或 `FY + 当前 YTD - 去年同期 YTD` 边界；输入不足时保持缺失原因，不乘四年化、不填零。

## 证据边界与样本索引

- 正式对照索引为 `docs/runbooks/L1.10C1_archive_comparison.json`，PIT 固定 `2024-11-18T00:00:00Z`。归档事实来自 12 个既有 SEC response body；合成 market byte 仅满足身份输入契约，不参与财务数值，也不是正式候选输入。
- KO、CAT、SNOW、PARA 的可组成指标及逐组成 oracle 位于该 JSON；修复后 KO CFO 的独立公式为 `11,599,000,000 + 2,854,000,000 - 8,929,000,000 = 5,524,000,000`，真实 PostgreSQL adapter 实际值相同。
- TSM 继续保持 IFRS/ADR 专用映射未闭合边界；JPM 保持 PIT 下无可见申报且既有行业路由 unsupported 的负例。本包不采购供应商数据、不补全这些映射。
- EPS 加权平均稀释股数与估值时点股本定义不在本包；未用 basic 回退 diluted，未修改市值/完全稀释估值分母、冻结权重、门槛、评分缺失规则、PIT、paper-only 或数据许可。
